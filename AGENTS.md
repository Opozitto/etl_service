# AGENTS.md

## Правила работы

- Один thread = одна задача.
- Не переписывать проект с нуля.
- Не расширять scope.
- Сначала проверка текущего состояния репозитория, потом изменения.
- После изменений делать только минимальные проверки, которые подтверждают конкретный результат.
- Если README, комментарии, прошлые чаты и код расходятся, источником истины считается код.
- Не менять production code, если задача явно про документацию или верификацию.
- В конце каждой задачи фиксировать:
  - что изменено
  - что проверено
  - какие риски остались

## Рабочий порядок

1. Снять фактическое состояние по коду, тестам, конфигам, README и командам запуска.
2. Отметить только подтверждённое.
3. Если чего-то не хватает, пометить как `не подтверждено`.
4. Делать минимальные точечные правки.
5. Проверить только то, что затронуто текущей задачей.

## Ограничения

- Не добавлять зависимости без отдельного запроса.
- Не менять архитектуру по умолчанию.
- Не расширять продуктовый контур за пределы текущего ETL / storage / search baseline.

## Окружение и команды Python

- Рабочее Python-окружение проекта: conda env `etl_env`.
- Источник истины для проверок — команды через `etl_env`, а не глобальный `python` из PATH.
- В Codex-задачах для проверок использовать явный формат:
  `conda run -n etl_env python -m pytest -q`
- Для установки зависимостей использовать:
  `conda run -n etl_env python -m pip install -e .[dev]`
- Для запуска проектных скриптов использовать:
  `conda run -n etl_env python -m scripts.rebuild_corpus`
  `conda run -n etl_env python -m scripts.demo_search --query "экология проект"`
- Не использовать `pip install ...` и `python ...` без явного `etl_env`, если задача относится к проекту.
- Если глобальный `python` указывает на base Anaconda, LibreOffice, WindowsApps или другой Python, это проблема shell/PATH, а не проекта.
- Не добавлять workaround-и в production code или tests для локальных проблем PATH/TEMP без отдельного запроса.
- Если pytest падает на локальной TEMP/TMP ACL-проблеме, не менять код и тесты; исправлять права/переменные среды вне проекта.

## Ограничение Codex sandbox на Windows

- На этой машине Codex запускает команды от пользователя `OPOZITPC\CodexSandboxOffline`.
- В Codex pytest может падать на `PermissionError` при работе с `tmp_path` / `pytest-of-*`, даже если тесты проходят в обычном `cmd`.
- Не исправлять эту локальную проблему через `conftest.py`, изменение tests или production code.
- Источник истины для pytest-регрессии — локальный запуск пользователем в `etl_env`:
  `conda activate etl_env`
  `python -m pytest -q`
- Codex может выполнять диагностику и точечные проверки, но если pytest падает только на sandbox temp/ACL, нужно остановиться и запросить локальное подтверждение у пользователя.
- Если `rg` в Codex sandbox на Windows упирается в ACL/PermissionError, можно использовать read-only PowerShell fallback (`Get-ChildItem`, `Select-String`, `Get-Content`).
- Такое поведение считается ограничением локального окружения, а не ошибкой проекта.
- Не добавлять workaround-и в production code/tests из-за проблем `rg` или ACL.
